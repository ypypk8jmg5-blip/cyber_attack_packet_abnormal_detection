## 1. 발표 관점 현재 상태 진단

현행 대시보드는 **운영자용 모니터링 화면**으로는 충실하지만, 발표 데모 화면으로는 다음 한계가 있다.

| # | 문제 | 코드 근거 | 발표 시 영향 |
|---|------|----------|------------|
| 1 | 글씨가 너무 작음 | 에이전트 뱃지 `font-size:10px` (`agents_panel.py`), 재현율 라벨 9px/포맷 8px (`phase1_panel.py`), 카드·바 전반 9~12px | 프로젝터 3m 거리에서 판독 불가 |
| 2 | 주인공(에이전트 그리드)이 조연 위치 | 좌측 컬럼 폭 280px (`app_window.py` `top_splitter.setSizes([280, 1000])`) | 데모의 핵심인 "32개 점등"이 화면 구석에서 일어남 |
| 3 | "깨어나는 순간"이 정적임 | `on_stdout_line()`이 한 번 ACTIVE로 바꾸면 종료까지 고정 — 펄스·감쇠 없음 | 점등 후 그리드가 죽은 그림이 됨. 협업 중이라는 인상 없음 |
| 4 | 키 이벤트가 로그 한 줄로 지나감 | 게이트 통과("Targets met"), CRITICAL 급증, 드리프트→재학습이 로그 패널 안에서만 표시 | 청중은 슬라이드 5의 3박자(기동·탐지·적응)를 화면에서 확인 못 함 |
| 5 | 데모 실패 보험이 없음 | 실행 경로가 QProcess 라이브 실행뿐 (`controller.py`) | 발표장 환경(가상환경·데이터·성능) 문제 시 보여줄 것이 없음 |
| 6 | 16:9 발표 화면 미고려 | 시작 크기 1280×820 고정, 풀스크린 모드 없음 | 프로젝터(1920×1080)에서 어중간한 창 + 작은 글씨 |
| 7 | 죽은 코드 | `gui/tabs/` 752줄 — 어디서도 import되지 않음 (panels로 대체된 구버전) | 유지보수 혼란 |

활용 가능한 숨은 자산: `logs/multi_agent_decisions.jsonl` — 패킷별 타임스탬프 + **에이전트별 투표(`votes`)** + 최종 판정이 이미 기록되고 있다. 리플레이와 투표 시각화의 데이터 소스로 그대로 쓸 수 있다.

## 2. 설계 원칙

1. **시그널 인터페이스 불변** — 패널들은 `state_changed / stdout_line / *_updated` 시그널만 본다. 발표 모드·리플레이를 이 인터페이스 뒤에 숨기면 기존 패널 코드 수정이 최소화된다.
2. **운영 뷰는 그대로** — 발표 모드는 토글(단축키/플래그)이며, 기본 실행은 현행과 동일하게 동작한다.
3. **덱과 1:1 대응** — 화면 연출 단위 = 발표 스크립트의 3박자(기동 → 탐지 → 적응).

## 3. 단계별 계획

### P0 — 발표 모드 (우선순위 최상, 약 1일)

`python3 run_gui.py --present` 또는 실행 중 `F5` 토글.

| 항목 | 내용 | 대상 파일 |
|------|------|----------|
| (a) 테마 토큰화 | 색상·폰트 크기를 `gui/theme.py` 상수로 추출, `scale()` 헬퍼 도입. 발표 모드 = 폰트 1.6×, 뱃지·카드 치수 동반 확대 | `gui/theme.py`(신설), 각 패널의 인라인 QSS 치환 |
| (b) 스테이지 뷰 | 발표 모드 전용 레이아웃: 에이전트 그리드를 중앙 60% 폭으로, 우측 레일에 대형 숫자 3개(탐지 건수·CRITICAL·현재 F1)만, 제어·로그 패널 숨김(`F6`으로 복귀) | `app_window.py` — QStackedWidget으로 운영 뷰/스테이지 뷰 2페이지 전환 |
| (c) 점등 연출 | 뱃지(QLabel)를 `AgentCell` 위젯으로 승격: ACTIVE 전환 시 250ms 플래시, 활동 라인 수신마다 재트리거, 3초 무활동 시 '온기 있는 유휴색'으로 감쇠. QVariantAnimation으로 배경색 보간 (스타일시트 직접 애니메이션 불가 — 구현 메모 참고) | `gui/widgets/agent_cell.py`(신설), `agents_panel.py` |
| (d) 이벤트 배너 | stdout 패턴·JSON 변화 감지 → 상단 오버레이 대형 배너 3초 표시. 감지 규칙: "Targets met"→`게이트 통과 (F1 X.XXX)`, CRITICAL 증가→`CRITICAL 알림 +N`, 드리프트/재학습 키워드→`재학습 트리거 — 드리프트 감지` | `gui/event_bus.py`(신설), `app_window.py` 배너 위젯 |

완료 기준: 1920×1080 풀스크린 스크린샷에서 에이전트 이름·핵심 숫자가 18px 상당 이상, 3박자 각각이 배너로 표시됨.

### P1 — 리플레이 모드 (데모 보험, 약 1일)

| 항목 | 내용 | 대상 파일 |
|------|------|----------|
| (a) 세션 레코더 | RUNNING 동안 stdout 라인 + 3개 JSON 스냅샷을 `logs/sessions/<ts>/events.jsonl`로 기록: `{"t": 상대초, "kind": "stdout"\|"dashboard"\|"metrics"\|"alerts", "data": …}` | `gui/session_recorder.py`(신설), `controller.py`에 옵트인 후크 |

| (c) 재생 컨트롤 | 재생/일시정지, 배속 1×/2×/4×, 구간 점프. 북마크 자동 마킹: 첫 ACTIVE(기동)·첫 CRITICAL(탐지)·재학습 트리거(적응) | `control_panel.py` 확장 |

## 4. 구현 메모 (함정 미리 표시)

- **스타일시트는 애니메이션 불가** — `QPropertyAnimation`이 QSS를 보간하지 못하므로, `AgentCell`은 `QVariantAnimation(QColor)` + `paintEvent` 또는 동적 `setStyleSheet` 콜백으로 색 보간한다.
- **배너는 오버레이** — 레이아웃에 넣으면 표시/숨김 시 화면이 출렁인다. `AppWindow` 자식 위젯으로 띄우고 `resizeEvent`에서 위치 고정.
- **리플레이의 mtime 의존 제거** — `DataMonitor`는 파일 mtime 폴링이므로 리플레이 시에는 사용하지 않고, `ReplayController`가 동일 시그널을 직접 방출한다 (앱 시작 시 둘 중 하나만 연결).
- **폰트 스케일은 QSS 토큰만으로** — `QApplication.setFont` 전역 변경은 matplotlib 캔버스·스핀박스 치수와 충돌하기 쉬움. `theme.scale()`을 거친 QSS 재생성 방식이 안전.
- **기존 발표 덱과의 정합** — 배너 문구·북마크 이름은 덱 슬라이드 5의 용어(기동/탐지/적응)와 동일하게 맞춘다.

## 6. 일정 요약

```
P0 발표 모드      ████████░░  약 1일   ← 다음 발표 전 필수
P1 리플레이 모드  ████████░░  약 1일   ← 데모 보험, 강력 권장
P2 서사 강화      ████░░░░░░  1~2일   ← 여유 시
```

P0 + P1 = 약 2일이면 "크게 보이고, 절대 실패하지 않는" 데모가 완성된다. P2의 투표 시각화는 차별화 요소로 가치가 높지만 발표 필수는 아니다.
